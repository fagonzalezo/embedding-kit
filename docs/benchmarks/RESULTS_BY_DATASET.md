# Results by dataset

What `EmbedKit().fit(X, y)` does to each of the 64 data sets of benchmark E10, compared with the embedding as the encoder produced it. Each data set is one source (for example CIFAR-100) embedded by one pretrained encoder (for example DINOv2): 35 text and 25 image classification sets, and 4 regression sets. The summary of the same runs, with the cost at scale and the retest of the hubness recommendation, is `docs/benchmarks/BENCHMARK_SELECTION.md`.

Generated by `benchmarks/report_datasets.py` from `benchmarks/results/e10/summary_datasets.csv`; do not edit by hand.

## In short

- **Never worse, often better.** The default is significantly better than the raw embedding on 43 of 64 sets and significantly worse on 0. Where it is better on a classification set it adds 0.8 to 15.1 points of kNN accuracy (median 4.3), which removes a median 24% of the remaining errors.
- **What it picks.** The refiner on 44 sets, the raw embedding on 19 and PCA on 1. Centring alone was never picked.
- **Weaker embeddings gain more.** The lower the raw accuracy, the larger the gain (Spearman -0.54 over the 60 classification sets; -0.92 on images). The encoders that gain most are GloVe (averaged), CLIP, ResNet-50; those that gain least are BGE, DINOv2.
- **Caution costs little.** On the 14 sets where another candidate scored higher on test than the one picked, the difference is at most 1.2 points.
- **kNN is what is optimised.** A linear probe on the output is better on 21 sets but worse on 5, by up to 0.8 points.

## Protocol

**Splits.** Every set has a fixed training split and a fixed test split (the sizes are in the source table below). The test split is used once, to score the final result; nothing is chosen on it.

**What the default does** (`EmbedKit()`, `strategy="select"`, with labels):
1. It holds out a random 20% of the training rows, stratified by class (`val_fraction=0.2`).
2. It fits each candidate on the other 80%:
   - **raw**: the embedding unchanged (`Identity`);
   - **centre + L2**: subtract the training mean, then scale each row to unit length;
   - **PCA → 64, 128, 256**: the top principal directions, then L2 normalisation (only the sizes below d);
   - **refiner**: a small network trained on the labels (described below).
3. It scores each candidate on the held-out 20% by cosine 10-NN classification accuracy (10-NN R² for a continuous target).
4. It keeps **raw** unless a candidate beats it with a paired bootstrap interval (95%, 2,000 resamples) entirely above 0, and then takes the best such candidate.
5. It refits the winner on all the training rows.

**The refiner.** There are two refiners, one for classification and one for regression, each a fixed configuration: the library's defaults, the same on every set, with nothing tuned per set. Only the weights are learned on each set. The output dimension is min(128, d / 2), which is 128 on all the sets here (the smallest d is 256).

| | Classification (`mode="supervised"`) | Regression (`mode="regression"`) |
|---|---|---|
| Architecture | residual adapter: z = normalise(W x̃ + g(x̃)), with x̃ the input standardised, W initialised at the top principal directions and g an MLP (hidden 256, 2 layers, dropout 0.1) whose output starts at 0, so training starts at PCA + L2 | MLP (hidden 256, 2 layers, dropout 0.1), L2-normalised output |
| Loss | supervised contrastive (SupCon), temperature 0.07 | Rank-N-Contrast, temperature 0.07 |
| Views per row | the row and one of its 5 nearest neighbours in the input (`KNNPairs(5)`) | two copies with Gaussian noise, 0.05 of each feature's standard deviation (`GaussianNoise(0.05)`) |
| Early stopping | on 10-NN accuracy of 10% of the fitting rows held out | on the R² of a ridge probe on 10% held out |
| Training | Adam, learning rate 3e-4, weight decay 1e-4, cosine schedule, batch 256, at most 100 epochs; evaluated every 5 epochs, stopped after 10 evaluations without improvement, best weights restored | the same |

**What is measured**, on the test split:
- **kNN accuracy** (primary, classification): the percentage of test rows whose 10 nearest training rows by cosine distance vote for the correct class.
- **kNN R²** (primary, regression): R² of predicting each test row's target as the mean target of its 10 nearest training rows by cosine distance. It can be negative (worse than predicting the mean).
- **Euclidean kNN accuracy**: the same vote with Euclidean distance.
- **Linear probe accuracy**: the test accuracy of a logistic regression (C = 1) trained on the transformed training rows. Not computed for regression.
- **Δ [95% CI]**: after minus raw, in accuracy points (R² for regression), with a paired bootstrap interval over test rows (2,000 resamples). **Bold**: the interval excludes 0 (significantly better). In the Euclidean and probe columns, ▲ and ▼ mark a significant rise or fall; a single number means the raw embedding was kept.

**Picked and best in hindsight.** *Picked* is what the default chose, using only its held-out training rows; it is what a user gets. *Best in hindsight* is the candidate with the highest test score, each fitted on all the training rows. It cannot be used in practice (choosing it needs the test labels) and its score is slightly optimistic, but the gap to it shows what the default leaves on the table. "same" means the picked candidate was also the best on test.

**Runs.** EmbedKit 0.7.0, one seed per set, one Quadro RTX 8000 GPU per run on the OCCIDATA cluster (2026-11-18 and 2026-11-19). *Fit time* is the whole `fit`: the selection and the refit. Text was embedded with sentence-transformers (any final normalisation removed, sequences cut at 256 tokens); images with each model's own preprocessing.

## Discussion

### Where the default helps

The gain depends on how much room the raw embedding leaves. Over the 60 classification sets the Spearman correlation between raw kNN accuracy and the gain is -0.54 (-0.92 on images, -0.34 on text), and within a source the encoder with the weaker raw score gains more in 8 of the 9 sources whose gains differ. The largest gains are on tasks with many classes (Flowers-102, CIFAR-100, MASSIVE) and on Emotion, which has 6 classes but a low raw accuracy: Flowers-102 (raw median 79.2%, better on 4 of 5, median gain 10.9 points); CIFAR-100 (raw median 71.1%, better on 5 of 5, median gain 7.4 points); MASSIVE (en-US) (raw median 81.4%, better on 7 of 7, median gain 6.0 points); Emotion (raw median 68.2%, better on 7 of 7, median gain 5.9 points). Small training sets are not an obstacle: Flowers-102 has 2,040 training rows for 102 classes (20 per class, 4 per class in the held-out part), and its gains are among the largest.

Among encoders, GloVe (averaged) (median +5.5), CLIP (median +4.1), ResNet-50 (median +4.0) gain most. Averaged GloVe vectors and ImageNet ResNet-50 features are older and weaker, and CLIP's image features were trained to match images with captions, not to separate fine-grained categories; this is a plausible reading, not something these runs test. BGE (median +0.0) and DINOv2 (median +0.2) gain least. DINOv2 is at 98% or more on 3 of its five sources; BGE is among the strongest text encoders here, and the default kept it raw on 3 of 5.

### Where the raw embedding is kept

The default kept the raw embedding on 19 sets. On most of them no candidate does much better even in hindsight: AG News (raw 89.9 to 91.5% with every encoder; at most 0.3 points from any candidate on test) and STL-10 (raw 97.7 to 99.6%; at most 0.4), and DINOv2 on Flowers-102 (99.6%).

20 Newsgroups is the exception: its raw accuracy is low (median 69.2%), yet the default improves it on only 1 of 7 encoders (GloVe, the weakest), and no candidate gains more than 1.2 points on the others even in hindsight. Emotion starts as low (median 68.2%) and improves on 7 of 7, by 5.9 points at the median. One reading: sentence encoders already arrange text by topic, which is what the newsgroup labels are, so reshaping the space cannot add much; the newsgroup errors may come from what the embedding does not contain (long posts cut at 256 tokens, overlapping groups). Emotion is not what these encoders organise by, and supervision can pull it forward. These runs do not test that explanation.

### What the caution costs

On 14 sets the candidate picked was not the best on test. On 13 of them the raw embedding was kept because no candidate's interval on the held-out rows lay above 0: with a held-out part of a few hundred to a few thousand rows, a gain under a point or so cannot be told from noise, and the rule then keeps the input. The largest such gap is 1.2 points (`newsgroups_mpnet`). On `stl10_vit`, PCA → 256 passed on the held-out rows and was 0.1 points below raw on test, inside the noise. The other side of that caution is that no set got worse.

### kNN against the linear probe

The selection scores candidates by kNN, and Euclidean kNN follows it (better on 41 sets, worse on 0). A linear probe is better on 21 sets but worse on 5: `flowers102_convnext` (-0.8), `pets_convnext` (-0.8), `pets_dinov2` (-0.7), `pets_vit` (-0.6), `stl10_vit` (-0.2). All are image sets where the raw probe is already at 93% or more. A likely reason is that the lower-dimensional output (128 or 256) keeps the neighbourhoods but drops some directions that a probe on the full embedding can use. If the downstream model is a linear classifier, compare with the raw embedding on held-out data before switching.

### Regression

The refiner was picked on all four regression sets and improved each one. The largest change is on TAPE fluorescence, where 10-NN on raw ESM-2 features scores below zero (R² -0.79, worse than predicting the mean; the test variants carry more mutations than the training ones, so this is extrapolation) and the refiner reaches 0.48. On Yelp the gain is +0.169.

### Cost

A whole `fit` took 9 s to 6.6 min (median 61 s) on one GPU, most of it training the refiner. The slowest sets have 50,000 training rows. Beyond 50,000 rows the selection runs on a subsample (`selection_max_rows`); `docs/manual.md` section 3.5 has time and memory up to a million rows.

## Limitations

- **One seed per set.** The intervals cover the sampling of test rows, not the randomness of training or of the held-out split.
- **kNN is the criterion.** The default optimises neighbour-based accuracy; other uses (linear probes, retrieval with other metrics, clustering) can differ, as the probe column shows.
- **With labels only.** Without labels the default is centre + L2, which no label-free score can validate; experiment E4 measured it (`benchmarks/results/e4/REPORT.md`).
- **Encoders as published.** Each encoder was used frozen with one pooling choice; fine-tuning the encoder itself is outside this comparison.
- **Geometry not reported.** How hubness, isotropy or intrinsic dimension change after the transform was not measured on these runs.
